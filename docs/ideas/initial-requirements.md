# 売上レポート自動化ワークフロー - アイデアメモ

## このドキュメントの位置づけ

このドキュメントは壁打ち・ブレストの成果物で、正式な仕様書ではありません。

## 背景

とある小売企業において、毎月の売上レポートは経理担当者が手動で作成している。

現状の作業フロー:
1. 売上データ(CSVファイル)をダウンロードする
2. Excelで集計処理を行う
3. レポートを作成する
4. 関係者にメールで送付する

この作業は毎月1日に行われる。

### 現状の課題

- 手作業のため、ヒューマンエラーが発生するリスクがある
- 担当者が不在の場合、レポート作成が遅れる
- 集計ロジックがExcelに依存しており、属人化している

### 目的

ワークフローの自動化により、売上データの集計からレポート送付までを自動化し、上記の課題を解消する。

## 実施手順(想定)

1. 要件を実現するためのAWS構成図を作成する
2. 構成図に従い、AWSマネジメントコンソールで実際に環境構築する
3. 構築後、動作確認を行う

## 要件(初期インプット)

### 要件1: 売上データの準備
- ストレージに売上データ(CSVファイル)を配置する

### 要件2: スケジュール実行
- 毎月1日の午前9時に自動的にワークフローが開始されること

### 要件3: ワークフローの構築
- 複数の処理を順番に実行するワークフローが構築されていること

### 要件4: 売上データ集計関数
- 売上データの集計関数が作成されていること

### 要件5: レポート作成関数
- レポート作成関数が作成されていること

### 要件6: メッセージキューによる非同期処理
- レポート作成関数からメール送信関数への連携は、メッセージキューを使用して非同期で行う
- メッセージキューにメッセージが入ると、自動的にメール送信関数が起動する

### 要件7: メール送信関数
- メール送信関数が作成されていること

### 要件8: エラーハンドリング
- メール送信に失敗した場合、一定回数リトライする
- リトライしても失敗したメッセージは、別のキュー(失敗用)に保持する
- 失敗したメッセージは後から確認・再処理できるようにする
